# UX laws for pages

Use these to explain why an issue changes user behavior. Name the law in the **Why** column only when it adds weight.

| Law | On a page, it means… | Look for |
|---|---|---|
| Fitts's law | Small or distant targets get mis-tapped | Targets under 44px; CTA out of thumb reach |
| Hick's law | More choices mean slower decisions | Competing CTAs; full nav on landing pages; long option lists |
| Jakob's law | Users expect patterns they know from other sites | Unusual controls; links that don't look like links |
| Von Restorff effect | The one thing that stands out gets remembered and clicked | The primary CTA doesn't out-contrast everything else |
| Serial position | First and last items stick | Weak opening; page ends with no CTA |
| Miller's law / chunking | People hold a few items at once | Long unbroken lists; specs with no grouping |
| Cognitive load | Every extra thought adds drop-off risk | Math the user has to do; jargon; unclear offers |
| Information scent | Users follow cues that promise what they want | Hero doesn't match the ad; vague link labels |
| Aesthetic-usability effect | Polished design reads as trustworthy | Inconsistent styling near proof or price |
| Social proof | Others' choices reduce risk | Ratings and reviews far from the ask |
| Proximity / common region | Things grouped together read as related | Price far from its CTA; labels detached from fields |
| Goal-gradient effect | Users speed up as they near the goal | No progress shown in multi-step flows |
| Doherty threshold | Responses under ~400ms keep users engaged | No loading or added feedback |
| Tesler's law | Some complexity can't be removed, only moved | Questions left for the user to work out |
| Peak-end rule | The best moment and the last moment shape the memory | Pressure tactics; a dead-end finish |
| Choice overload | Too many options lead to no decision | Too many products or variants with no guidance |
